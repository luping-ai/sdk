# 图形界面演示

一个窗口里逐项体验 SDK 的能力。左侧选功能，右侧操作，底部状态栏。

## 运行

```bash
python examples/gui/app.py
```

需要：
- 已安装 SDK（`pip install luping-localai`，或在仓库里用 `.venv` 的解释器）
- Local AI Hub Runtime 已启动

> **Windows 上若 `python` 没反应**（退出码 9009），说明它指向应用商店
> 占位符。改用 `.venv\Scripts\python examples\gui\app.py` 或 `py`。
> 详见上级目录 README 的「先确认环境」。

启动后会自动尝试连接 Runtime，通常不需要手填任何东西。

## 五个面板

| 面板 | 演示什么 |
| --- | --- |
| **连接与健康** | 自动发现（不写死端口）、三态健康检查、检查项明细 |
| **能力与模型** | 能力分级（对话/RAG 可用性）、模型清单表格、当前加载高亮 |
| **对话（多轮）** | 聊天框样式：消息气泡左右分栏、历史累积可见、流式逐字、停止生成 |
| **结构化输出** | 约束解码；可在「有上限 / 无上限」两种 schema 间切换对比 |
| **知识库（RAG）** | 建库 → 导入（示例文本或选文件）→ 检索 → RAG 问答 → 删除 |

## 三个值得亲手试的地方

**1. 流式是真的逐字出现**

在「对话」面板发一句"数一到十"，观察第一个字出现的速度。

界面是聊天框样式：你的消息在右侧绿色气泡，助手的在左侧灰色气泡。
发两轮就能看到多轮上下文真的生效——先说"我叫李娜"，再问"我叫什么
名字"，它会答出来。右上角会显示"已进行 2 轮 · 下次请求会带上全部
4 条消息"，这正是 `messages` 数组在累积。

点「停止」会断开 HTTP 连接，服务端随即停止生成。**被停止的那一轮
不会进历史**——否则残缺的回答会污染后续几轮的上下文。

**2. 结构化输出：有上限 vs 无上限**

「结构化输出」面板上有两个 schema 选项，切换后各跑一次：

| Schema | 预期结果 |
| --- | --- |
| 有上限（带 `maxItems` / `maxLength`） | 几秒返回，JSON 合法 |
| 无上限（只有 `type`） | **卡二十几秒**，撞上 `max_tokens` 被截断，JSON 断在字符串中间 |

这不是 bug，而是约束解码的真实边界：它能阻止模型输出 schema 外的
内容，**挡不住它无限重复合法内容**。把 `max_tokens` 调大也没用——
只会让截断点更靠后。

修法永远在 schema 一侧：数组加 `maxItems`、字符串加 `maxLength`、
自由字符串改 `enum`。

**3. 知识库的正常状态看起来像错误**

- 导入同一份文件两次 → `duplicate=True`，但**不是错误**（按内容 SHA-256 去重）
- 没配 Embedding 模型时点「仅检索」→ 提示**已降级**，但关键词检索仍可用
- 上下文一条都没注入 → 通常是 `context_tokens` 小于固定开销（防注入声明占的 token）

这些都在界面里明确标出来了，避免用户把自己的配置问题当成程序故障。

## 代码结构

```
gui/
├── app.py        主窗口：左侧导航 + 右侧面板 + 状态栏
├── tasks.py      后台线程 → 主线程的结果回传
├── widgets.py    复用控件：只读文本、字段表、状态栏、忙碌按钮
└── panels/
    ├── connect.py      连接与健康
    ├── capability.py   能力与模型
    ├── chat.py         对话（聊天框 + 多轮）
    ├── structured.py   结构化输出
    └── knowledge.py    知识库
```

### 为什么对话用 Canvas 而不是 Text

最初用 `Text` 的 tag 做气泡（背景色 + `lmargin`/`rmargin` 缩进），
**做不到**：Text 的 tag 背景覆盖整个逻辑行，`lmargin`/`rmargin` 只移动
行边界，背景依然铺满窗口宽度。结果是"整行换色的日志"，不是气泡。

截图验证过这一点后才改用 Canvas：每条消息是一个 `tk.Label`，放在
`tk.Frame` 里用 `anchor` 决定左右，`wraplength` 控制最大宽度
（窗口宽度的 72%），窗口缩放时同步调整。这才是真的气泡。

流式追加也简单：助手气泡就是一个 Label，逐段 `configure(text=...)`，
tkinter 自动重算高度。

### 为什么需要 `tasks.py`

tkinter 是**单线程**的：所有控件操作必须在创建 Tk 的那个线程里做。
而 SDK 的调用可能阻塞几十秒（模型冷启动、文档解析）。在主线程里直接
调用会让窗口"未响应"。

所以统一约定：

```
后台线程做事 → 结果放进 queue → 主线程定时取出并更新界面
```

各面板的 `_do_xxx` 方法都是这个形状：`runner.submit(work, on_done=..., on_error=...)`。

> 这里踩过一个坑值得记下：最初 `TaskRunner._bump(-1)` 在后台线程的
> `finally` 里直接调用了界面回调，于是 `Progressbar.stop()` 在非主线程
> 碰了 tkinter，抛 `RuntimeError: main thread is not in main loop`。
> 忙碌状态也必须走队列——现在 `poll()` 统一在主线程派发。

### 为什么用 tkinter

它是标准库自带的，所以这个演示**不引入任何依赖**，与 SDK 本身的
零依赖约束一致。PyQt/PySide 界面更好看，但要额外装几十 MB，对一个
"看 SDK 能做什么"的演示来说不值。

## 已知限制

| 项 | 说明 |
| --- | --- |
| 无图形环境无法运行 | SSH、容器、CI 里没有显示服务。用命令行版 `examples/demo.py` |
| 界面较朴素 | tkinter 的限制。功能完整，视觉上不追求精致 |
| 不支持拖拽导入 | 「选择文件导入」用的是系统文件对话框；拖拽需要额外的 tkdnd 扩展 |
| 未做多语言 | 界面文案是中文 |
